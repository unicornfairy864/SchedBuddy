## 一、全局要求与规定

1. **形态**：桌面应用 + 局域网 Web 双端；仅限本地与局域网，不做公网。**规划扩展（v0.3–0.5，已决策）**：新增第三端 **Android App 移动写端**（React Native + TS，内置库离线可用、仅局域网手动同步），详见 §三。
2. **产品位置**：成品全部位于 `app/` 文件夹 —— 代码、文档、运行时数据库（`app/data/schedbuddy.db`、`backups/`）、资源（`app/resources/avatar.jpg` 等）。
3. **依赖安装**：每次下载/安装依赖都必须先给用户清单并经**手动确认**。
4. **版本与 Git**：
   - 使用 git 管理，主分支 `main`；
   - **每一次对话结束都修改版本号并提交至 git**；
   - **大版本（x.0.0）修改必须获得用户授权**；
   - 版本权威来源：`app/package.json` + `app/CHANGELOG.md`（规则详见 `05-versioning.md`）。
5. **技术栈（已授权确认）**：Electron（桌面壳）+ React + TypeScript + Vite + Node(Express) + SQLite(better-sqlite3)，npm workspaces 单仓库；**一份前端代码桌面与 Web 双端复用**。**规划扩展（2026-09-05 决策）**：Android App 采用 **React Native + TypeScript**，直接复用 `shared` 引擎与布局计算。
6. **写入权限**：桌面端本机 = 唯一可写主机（内置后端+数据库，常驻服务）；局域网设备通过浏览器访问**同一份数据、只读**（后端按 socket 来源地址强制，非回环写请求 403）。
7. **UI 要求**：简洁、美观、清新（浅色主题，简体中文）；所有可交互元素有**反馈动画**（按钮按压、块 hover 聚焦 + 悬浮窗快速淡入淡出、删除/新建动效等）。
8. **数据与规则**：四种日程（固定/特定/可选/临时，按重要度排序）+ 可扩展规则引擎；视图为“横向时间轴 + 圆角块”的周/日两种。完整口径见 `00-decisions.md`、`02-data-model.md`、`03-ui-spec.md`。
9. **打包**：安装程序（electron-builder）已按用户要求**搁置**；待用户明确指令后再做（届时先提交 Electron 依赖清单确认）。
10. **验收模式**：用户可就改动逐项验收，**通过一项才执行下一项**。
11. **文档同步（本规则于文档版生效）**：功能/界面/规则/文档发生任何修改后，必须同步更新本说明文档、`` 对应章节与 `app/CHANGELOG.md`，保持“文档 = 现状”。
12. **遵循开发规范**：代码/命名/提交/测试/安全等一律执行 `06-dev-conventions.md`（提交信息用 Conventional Commits 中文格式）。
13. **遵循文档规范**：文档体系、元信息、更新流程与术语口径执行 `07-doc-standards.md` 与 `08-glossary.md`。

## 二、已完成内容

### 里程碑
- **v0.1.0**：初始化 git 仓库与 npm workspaces 骨架（shared/server/web/desktop）+ 全套设计文档。
- **v0.2.0**（核心引擎 + 服务端 + 只读视图）：
  - `shared` 规则引擎（纯函数，浏览器/服务端共用）：固定星期多段、单/双周、隔 N 天、一次性、生效日期范围；单次跳过/改期；冲突检测（自身重叠与 fixed×fixed=硬冲突，其余=警告）；排布算法 packDay（**自下而上按重要度贪心入排、同排可混合类型、永不产生空排**，底排空闲区画绿）；引擎自测通过（`npm test`）。
  - `server`：Express + SQLite（better-sqlite3，结构迁移至 v2）、自动备份、写保护守卫、REST API（schedules/occurrences/settings/export/import）、冲突策略 409 + force；演示种子 `npm run seed:demo`。
  - `web`：周/日视图只读渲染（横向“日带”、hover 悬浮窗、现在线、今天高亮、周/日切换），类型默认色。

### 验收与 UI 微调轮次（v0.2.1 → v0.2.14）
- 周视图填满可视区；日视图「上午 0:00–12:00 / 下午 12:00–24:00」两条半天带 + 自动裁首尾空余 + 跨 12 点日程视为同一整体；
- 全局字号放大（正文 16px）；头像（`avatar.jpg`）作为 Logo；时间切换与周/日切换归组；
- 无日程之日不渲染空排，周视图日带高 = 行数 × 单位行高（2 行=2 份、空日=1 份）；
- 删除页脚图例文字；日视图大块始终显示名称（晨跑等短块）；日视图垂直居中；
- 悬浮窗防越界（靠近视口顶部/右侧自动翻转）与**淡入 + 淡出动画**、离开方块即隐藏；
- 日视图任何日期固定显示上午/下午两带（某半天无日程不再隐藏）；
- 标尺数字居中于刻度线正下方、首/尾数字防溢出（首靠右/尾靠左）、补全 24:00 刻度线与标签。

### v0.2.23（v0.3 起步 · 顶栏重构）
- 顶栏改「单行一体」分区（详见 `03-ui-spec.md` §7）：品牌（SchedBuddy + 版本号于名下方小字）→ 周/日切换 → 日期导航 → 右操作区；版本号不再占右侧。

- 断点体系新增档位（900/720/480，板面内容仍 860），规范同步：`06-dev-conventions.md` §5、`03-ui-spec.md` §7、`00-decisions.md` ADR。

### v0.2.26（验收项 2）
- 日期范围拆分「日期段 + 周次段」：空间不足先省略日期段（≤430px 隐藏），**第N周常驻**；无学期起点时日期段回退显示。

### v0.2.27（验收项 3；验收项 4「日常/周常区分」经用户确认取消）

### v0.2.29（v0.3 数据层起步 · 同步字段落库，2026-09-05）
- `schedules`/`settings` 迁移 v3：新增 **`rev`**（单调同步序号，每次写 +1）、**`deleted_at`**（软删墓碑）、**`last_writer`**（设备 id）；既有行补基线 rev=1。
- DELETE 改**软删**（置墓碑并 rev+1，删除可随同步双向传播）；列表/展开/冲突检测只含在册记录，墓碑保留供 v0.5 pull 消费。
- shared `Schedule` 类型增加 `rev`/`deletedAt`/`lastWriter`；服务端强制维护同步字段（客户端提交值一律忽略）；`setSettings` 每次写维护 rev/last_writer。
- 引擎自测 13 组通过；API 冒烟通过（rev 递增、软删隐藏、墓碑保留、注入字段被忽略）。

### v0.2.30（v0.3 编辑 UI 起步 · 弹窗表单与冲突交互，2026-09-05）
- 本机可写端接入 **新建/编辑/删除弹窗**：名称、四类日程、颜色选择（常用色板/取色器/`#RRGGBB`/随机）、规则切换（固定星期/隔 N 天/一次性）、多段时段增删、单双周（含锚点）、生效范围、备注。
- **冲突告警交互**：硬冲突红条 + 「强制保存」勾选（409 + force）；警告黄条 + 「仍要保存」二次确认；服务端 400/409 摘要展示。
- 删除走 v0.2.29 的软删 API，编辑弹窗内二次确认；保存/删除后静默刷新 + Snackbar。
- 入口：顶栏「＋ 新建」/ 点击方块 → 悬浮窗「✎ 编辑」（仅本机；LAN 只读端保持只读无入口）。
- **设置面板**：学期起点/结束/周数读写，保存后即时生效（第 N 周/单双周提示刷新）。
- Web 改动：`api.ts`（REST 封装 + ApiError）、`ScheduleModal.tsx`、`SettingsModal.tsx`、`DayBands` 点击接线、`App.tsx` 状态接线、样式（弹窗/色板/时段行/冲突条/动画）。

### v0.2.32（编辑入口移至悬浮窗「✎ 编辑」按钮，2026-09-05）
- 点击方块不再直接编辑：改为固定 sb-tip 悬浮窗 → 窗内点「✎ 编辑」打开编辑弹窗（移动端点按适配，一次点按固定、再点按钮编辑）；固定态悬浮窗可交互（移向窗口不消失、Esc/点窗外/离开窗口取消固定）；只读端无编辑按钮。
- 细节见 `03-ui-spec.md` §2/§3（v0.2.32 同步）。

### v0.2.33（删除时间线直接添加入口，2026-09-05）

### 演示与验证
- 演示数据：高等数学（固定）、大学英语、人文通识、篮球社（单周）、吉他社（双周）、晨跑（隔 2 天）、毛概（水课·与高数重叠警示）、ACM 校赛（一次性）。
