## 一、全局要求与规定

1. **形态**：桌面应用（**可选主机**）+ 局域网 Web（只读）+ **Android App（本地优先 · 离线独立）** 三端。App 内置数据库为**自身权威副本**，无电脑时**单机完整可用**；桌面/网页是额外工作入口与**可选同步对端**。仅限本地与局域网，不做公网。详见 `00-decisions.md` §1/§5 与 §三。
2. **产品位置**：成品全部位于 `app/` 文件夹 —— 代码、文档、运行时数据库（`app/data/schedbuddy.db`、`backups/`）、资源（`app/resources/avatar.jpg` 等）。
3. **依赖安装**：每次下载/安装依赖都必须先给用户清单并经**手动确认**。
4. **版本与 Git**：
   - 使用 git 管理，主分支 `main`；
   - **每一次对话结束都修改版本号并提交至 git**；
   - **大版本（x.0.0）修改必须获得用户授权**；
   - 版本权威来源：`app/package.json` + `app/CHANGELOG.md`（规则详见 `05-versioning.md`）。
5. **技术栈（已授权确认）**：Electron（桌面壳）+ React + TypeScript + Vite + Node(Express) + SQLite(better-sqlite3)，npm workspaces 单仓库；**一份前端代码桌面与 Web 双端复用**。**Android App 采用 React Native + TypeScript**（Expo SDK，v0.4 已落地），复用 `shared` 引擎（展开/日期/校验/冲突）与数据口径。
6. **数据与同步（v0.4.1 修订：本地优先，取消"唯一权威主机"）**：App 与桌面各自持有**本地完整副本**（各自可独立全功能使用）；同一局域网内由用户**手动双向同步**（pull / push / merge，冲突逐条裁决：留本机版 / 留对端版 / 手动合并）；删除经墓碑双向传播。局域网浏览器仍只读（后端按来源/设备 token 控制写）。详见 `00-decisions.md` §5 决策日志（v0.4.1 三行）。
7. **UI 要求**：简洁、美观、清新（浅色主题，简体中文）；所有可交互元素有**反馈动画**（按钮按压、块 hover 聚焦 + 悬浮窗快速淡入淡出、删除/新建动效等）。
8. **数据与规则**：四种日程（固定/特定/可选/临时，按重要度排序）+ 可扩展规则引擎；视图：**Web/桌面 = "横向时间轴 + 圆角块"的周/日两种**；**移动端（v0.4 定案）= "纵向日卡列表"的周/日两种**（复用 shared 展开/日期引擎，竖屏适读，不移植时间轴）。完整口径见 `00-decisions.md`、`02-data-model.md`、`03-ui-spec.md`。
9. **打包/桌面端**：桌面壳已起步（v0.3.5 架构：随包 node.exe 子进程跑后端，better-sqlite3 仅编译给系统 Node、**用户端无需安装 Node/编译环境**）；`npm run dist:dir` 产出 win-unpacked 目录即用。**桌面打包为按需操作**：仅在明确要求分发/换用桌面包时执行，**不随每次代码更新自动打包**（构建只做 shared/server/web）。NSIS 安装包 / 自定义图标为后续可选项（再做前先提交依赖/配置清单确认）。
10. **验收模式**：用户可就改动逐项验收，**通过一项才执行下一项**。
11. **文档同步（本规则于文档版生效）**：功能/界面/规则/文档发生任何修改后，必须同步更新本说明文档、`` 对应章节与 `app/CHANGELOG.md`，保持“文档 = 现状”。
12. **遵循开发规范**：代码/命名/提交/测试/安全等一律执行 `06-dev-conventions.md`（提交信息用 Conventional Commits 中文格式）。
13. **遵循文档规范**：文档体系、元信息、更新流程与术语口径执行 `07-doc-standards.md` 与 `08-glossary.md`。

## 二、已完成内容

### 里程碑
- **v0.1.0**：初始化 git 仓库与 npm workspaces 骨架（shared/server/web/desktop）+ 全套设计文档。
- **v0.2.0**（核心引擎 + 服务端 + 只读视图）：
  - `shared` 规则引擎（纯函数，浏览器/服务端共用）：固定星期多段、单/双周、隔 N 天、一次性、生效日期范围；单次跳过/改期；冲突检测（自身重叠与 fixed×fixed=硬冲突，其余=警告）；排布算法 packDay（**自下而上按重要度贪心入排、同排可混合类型、永不产生空排**，底排空闲区画绿）；引擎自测通过（`npm test`）。
  - `server`：Express + SQLite（better-sqlite3，结构迁移至 v2）、自动备份、写保护守卫、REST API（schedules/occurrences/settings/export/import）、冲突策略 409 + force；演示种子 `npm run seed:demo`。
  - `web`：周/日视图只读渲染（横向“日带”、hover 悬浮窗、现在线、今天高亮、周/日切换），类型默认色。
- **v0.3.0（已定版，2026-09-05）**：PC/Web **编辑核心**里程碑完成 —— 由 v0.2.29–0.2.55 迭代落地：同步字段（迁移 v3）与软删、新建/编辑/删除弹窗、冲突告警（红/黄前置不拦保存、红自动 force）、设置面板、弹窗控件升级（自绘下拉 / 日期三段+日历 / 时间时:分 / 连续输入流）、「高级」折叠区（单双周 + 生效限制：日期范围 / 课程总数量，迁移 v4 + 引擎按天截止）、删除退场动画、日带 gutter「＋」、桌面悬浮窗可接鼠标。引擎自测 15 组。
