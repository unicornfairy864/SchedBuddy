# 07 · 文档规范（Documentation Standards）

> 状态：生效　·　适用范围：仓库全部 markdown 文档　·　最近更新：v0.2.21（2026-09-04）

## 1. 文档体系

```
docs/项目说明.md          总纲：全局要求/已完成/未来规划（仓库根 docs/，与 app/ 同级）
app/docs/
├─ 00-decisions.md        需求基线 + 决策记录（含 术语约定）
├─ 01-architecture.md     架构、目录、里程碑
├─ 02-data-model.md       数据模型与规则引擎（含 JSON 示例）
├─ 03-ui-spec.md          UI 规范与验收清单
├─ 04-api.md              API 约定（含请求/响应示例、错误码）
├─ 05-versioning.md       版本与 Git 规范、文档同步规定
├─ 06-dev-conventions.md  开发规范（代码/命名/提交/测试/安全）
├─ 07-doc-standards.md    本文档
└─ 08-glossary.md         术语表
app/CHANGELOG.md          版本变更记录（与每次版本提交同 commit）
```

## 2. 文档元信息（每个文档标题下必须有）

模板：

```markdown
> 状态：`生效` ｜ `草稿` ｜ `待修订` ｜ `已废弃`
> 适用范围：……　·　最近更新：v<版本>（YYYY-MM-DD）
> 冲突仲裁：依赖/决策以上位文档为准；修改本文件须同步 CHANGELOG。
```

- 状态取值：正在执行的为**生效**；规划未定稿为**草稿**；内容与实际不符待修为**待修订**；已被取代为**已废弃**。
- “最近更新”随每次实质修改更新（与版本号一致）。

## 3. 撰写约定

- 语言：简体中文；术语一律查 `08-glossary.md`，不得一词多义（如 排 lane / 带 band / 时段 segment 不可混用）。
- 日期 `YYYY-MM-DD`；时间用 24h `HH:mm`；分钟内与毫秒在文档中标注单位。
- 命令块标注所在目录与平台（PowerShell）；路径相对仓库根；关键路径用行内代码。
- 引用别处文档使用相对链接（`../docs/…`、`02-data-model.md`）。
- 图表优先 ASCII/文本；表格列少而全；示例 JSON 必须可运行/可校验（与真实 API 保持一致）。
- 每篇文档职责单一、自上而下：先结论/口径，再细节/示例/FAQ。

## 4. 更新流程（修改后必须执行）

1. 定位受影响文档：总纲（项目说明）/ 决策(00)/ 架构(01)/ 数据(02)/ UI(03)/ API(04)/ 版本(05)/ 规范(06/07)/ 术语(08)/ CHANGELOG。
2. 只改相关章节，保持“文档 = 现状”；同时更新被引用示例与文件头“最近更新”。
3. 行为变化先落 `00-decisions.md`（含否决记录，注明版本），再改实现文档。
4. 提交时 CHANGELOG 与版本提交同 commit；若改动只是排版，仅 bump 文档版本行可不动代码版本。

## 5. 决策记录（ADR-lite）

重大或易误解的决策在 `00-decisions.md` §决策日志 登记：`日期 | 决策 | 理由 | 影响 | 版本`；已否决/回滚的决策保留并标注“作废（原因、版本）”，不删除历史。
