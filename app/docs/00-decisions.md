# 00 · 需求确认与决策记录

> 状态：生效　·　最近更新：v0.2.23（2026-09-05）　·　规范：`07-doc-standards.md`

> 本文件是**需求基线**：每次对话的疑问与结论都会同步到这里，实现以它为唯一口径。

## 0. 产品定位

帮助大学生把"脑子里的日程"可视化：
- 加入多个社团 → 单周/双周、隔 N 天、特定日期的社团活动；
- 主课 → 固定时间（不可变）；选修（水课）→ 可选上或不上；竞赛考试 → 临时一次性；
- 通过"周/日视图 + 时间轴横向条"看清每天重叠冲突，辅助决策（翘水课、考试提前交卷等）。

## 2. 四类日程（重要性从高到低）

| 类型 | type | 含义示例 | 重要度(越小越靠下/越先排) |
| --- | --- | --- | --- |
| 固定日程 | `fixed` | 数学课：每周一 8:00–9:30、周三 10:00–11:30 | 0（最先入排，通常落在最底排） |
| 特定日程 | `specific` | 社团活动：单周周二 18:00–20:00；隔 3 天训练 | 1 |
| 可选日程 | `optional` | 选修（水课） | 2 |
| 临时日程 | `temporary` | 竞赛考试（一次性某日某时） | 3 |

> 预留可扩展空间：类型、规则均为可扩展枚举 + JSON 参数，未来新增类别不改表结构（见数据模型文档）。

## 3. 字段要求（每个日程）

名称、备注、颜色（创建时选择）、时段列表（**多段**：每段 = 星期几或日期 + 开始 + 结束）、规则（见下）、生效日期范围（可选）、单次例外（后续）。

### 规则（已确认首批 + 待排期）

1. **固定星期多段** `weekly`：段列表按周重复，可叠加生效范围；
2. **单双周**：基于"学期第 1 周周一"锚点，标记 `odd` / `even`（与 weekly 组合）；若未配置学期起点则创建时提示填写；
3. **隔 N 天** `interval`：自起始日期起每 N 天发生一次；
4. **生效日期范围** `activeFrom/activeTo`：只在该范围（如第 1–16 周对应日期，或学期起止）内发生；
5. **重叠冲突检测与告警**：创建/编辑时列出重叠，按策略「拒绝 / 警告可强制」；
6. **单次跳过 / 单次改期**（occurrence override）：对具体某一次发生做例外，不改变规则本身。

### 我在规格外补充的设计决策（可推翻）

- **冲突策略**：两个 `fixed` 重叠 → 默认**拒绝**（可勾选强制保存）；其余任何组合重叠 → 黄色警告，允许强制保存。原因是"两门主课不能同时上"是硬约束，而社团/选修/考试冲突是用户要决策的对象。
- **颜色**：`fixed` 默认红 `#E4574E`，可在创建时修改；底部空闲带为浅绿；其余类型默认色 + 自由取色。
- **时段重叠判定**：`[开始, 结束)` 半开区间；同一日程自身重叠（同段）按错误提示。
- 每期对话递增版本并提交；大版本与依赖安装需授权（见 `05-versioning.md`）。

## 4. 范围边界（本期先做，后续对话扩展）

- 视图：**周 / 日**两种；月视图、学期总览、拖拽改期等列入 backlog。
- 桌面壳接入：源码可运行优先级 > 安装包分发。
- 本机 = 唯一可写主机；LAN 只读由后端按 socket 地址强制。
